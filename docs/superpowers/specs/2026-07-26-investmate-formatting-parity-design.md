# Форматирование по образцу InvestMateMobile

## Цель

Сделать механическое форматирование и базовые стилистические проверки FitnessMateMobile
совместимыми с локальным проектом InvestMateMobile.

## Подход

Перенести полный набор инструментов форматирования:

- Prettier как источник истины для механического форматирования;
- `@stylistic/eslint-plugin` и правила обязательных фигурных скобок и пустых строк;
- настройки VS Code для форматирования и исправлений при сохранении;
- npm-команды для форматирования, исправления и полной проверки.

Текущий CommonJS-файл `eslint.config.js` сохраняется. Правила из эталонного
`eslint.config.mjs` адаптируются к существующему формату, чтобы не создавать
необязательное переименование конфигурации.

## Изменения

- Добавить `prettier` и `@stylistic/eslint-plugin` в `devDependencies`.
- Добавить `.prettierrc.json` с шириной строки 100 и одинарными кавычками.
- Добавить `.vscode/settings.json` и `.vscode/extensions.json` по образцу InvestMateMobile.
- Дополнить `eslint.config.js` стилистическим плагином и правилами из эталона.
- Добавить команды `lint:fix`, `format`, `format:check` и `fix`.
- Обновить `check`, чтобы он последовательно запускал форматирование, типы, ESLint и тесты.
- Запустить автоматическое форматирование существующих поддерживаемых файлов.

## Границы

- Исходный репозиторий InvestMateMobile остаётся неизменным.
- Пользовательский файл `TODOS.md` не изменяется и не добавляется в коммиты.
- Не переносится документационная политика из `AGENTS.md`: задача касается инструментов
  форматирования, а не требований к содержанию исходного кода.
- Не создаётся общий внешний пакет конфигурации для двух независимых репозиториев.

## Проверка

После переноса выполняются:

1. `npm run fix`;
2. `npm run check`;
3. `git diff --check`.

Успех означает, что форматирование, типизация, ESLint и тесты проходят без ошибок, а
повторный запуск проверки форматирования не создаёт изменений.
