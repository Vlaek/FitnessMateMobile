# Префиксы типов и правила пустых строк

## Цель

Привести именованные интерфейсы и типы FitnessMateMobile к единому соглашению и
автоматически поддерживать его через ESLint.

## Именование

- Каждый объявленный в проекте `interface` получает префикс `I`.
- Каждый объявленный в проекте `type` получает префикс `T`.
- После префикса используется PascalCase: `DatabaseAdapter` становится
  `IDatabaseAdapter`, `ExerciseRecord` — `TExerciseRecord`, `Props` — `TProps`.
- Правило применяется к экспортируемым, локальным, внутренним и тестовым объявлениям.
- Все импорты и ссылки обновляются вместе с объявлениями.
- Внешние типы библиотек, generic-параметры и анонимные объектные типы не
  переименовываются.

## Пустые строки

- Между соседними инструкциями `import` пустые строки запрещены независимо от
  источника импорта.
- Между любыми соседними объявлениями `type` и `interface` обязательна одна пустая
  строка.
- Остальные действующие правила пустых строк сохраняются.

Например:

```ts
export type TExerciseRecord = {
  exerciseName: string;
  maxWeightKg: number;
  maxSetVolumeKg: number;
  trend: { date: string; maxWeightKg: number; volumeKg: number }[];
};

export type TAnalytics = {
  totalWorkouts: number;
  weeklyVolumeKg: number;
  records: TExerciseRecord[];
};
```

## Автоматизация

В `eslint.config.js` добавляются:

- отдельные `@typescript-eslint/naming-convention` для `interface` и `typeAlias`;
- запрет пустых строк между соседними импортами;
- обязательная пустая строка между соседними `type`/`interface`.

Переименование существующего кода выполняется как механическая операция с
проверкой всех ссылок TypeScript. Затем `npm run fix` применяет правила пробелов.

## Проверка

После изменений выполняются:

1. поиск объявлений без нужного префикса;
2. поиск пустых строк между импортами;
3. `npm run check`;
4. `npx expo-doctor`;
5. `git diff --check`.

Пользовательский `TODOS.md` не изменяется и не добавляется в коммиты.
