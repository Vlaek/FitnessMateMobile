# Публикация FitnessMate в RuStore

Этот документ описывает подготовку, сборку и публикацию Android-версии FitnessMate в RuStore.

Актуально для текущей конфигурации проекта:

- приложение: `FitnessMate`;
- Android package name: `ru.fitnessmate.mobile`;
- версия приложения: `1.1.0`;
- Expo SDK: `57`;
- сборка: Expo Application Services (EAS);
- EAS Project ID уже указан в `app.json`;
- профиль `production` уже создан в `eas.json`;
- номер Android-сборки увеличивается автоматически (`autoIncrement: true`, `appVersionSource: remote`).

> Важно: требования магазинов меняются. Перед фактической отправкой следует повторно проверить ссылки из раздела [Официальная документация](#официальная-документация).

## 1. Определить способ публикации

RuStore принимает два формата:

- **APK** — готовый установочный файл, уже подписанный разработчиком;
- **AAB** — Android App Bundle, из которого RuStore создаёт APK для конкретных устройств.

Для первой публикации FitnessMate рекомендуется один из вариантов:

### Вариант A — APK

Самый простой вариант для первой ручной публикации. EAS подписывает APK, после чего файл можно сразу загрузить в RuStore.

Плюсы:

- не нужно отдельно готовить подпись приложения для обработки AAB в RuStore;
- файл можно установить на устройство и проверить до отправки;
- проще диагностировать проблемы первой публикации.

Минус: пользователи обычно скачивают файл большего размера, чем при распространении через AAB.

### Вариант B — AAB

Текущий профиль `production` в EAS по умолчанию создаёт AAB. Для его загрузки RuStore потребует:

1. подписанный AAB;
2. сертификат ключа загрузки в формате PEM;
3. ZIP-архив с подписью приложения, подготовленный по инструкции RuStore.

Этот вариант имеет смысл использовать, если уже настроен процесс публикации AAB и обеспечено безопасное хранение ключей.

## 2. Создать аккаунт разработчика RuStore

1. Открыть [RuStore Консоль](https://console.rustore.ru/).
2. Авторизоваться через VK ID.
3. Выбрать тип аккаунта:
   - **физическое лицо** — подходит для публикации бесплатного приложения без монетизации RuStore;
   - **ИП или юридическое лицо** — требуется для платного приложения, подписок и встроенных покупок через RuStore.
4. Заполнить регистрационные данные.
5. Для ИП или юридического лица пройти подтверждение организации. Может потребоваться УКЭП и КриптоПро либо другой способ, доступный в консоли на момент регистрации.
6. Дождаться активации аккаунта.

Добавить новое приложение может пользователь с ролью владельца. Загружать версии также могут администратор, релиз-менеджер и разработчик.

## 3. Зафиксировать идентификатор и подпись приложения

Текущий Android package name:

```text
ru.fitnessmate.mobile
```

После первой публикации менять его нельзя: другой package name будет считаться другим приложением.

Все обновления должны быть подписаны тем же ключом, что и первая опубликованная версия. Потеря ключа может лишить пользователей возможности получать обычные обновления.

### Если FitnessMate уже опубликован в другом магазине

До первой публикации в RuStore необходимо определить:

- каким сертификатом подписана доступная пользователям версия;
- есть ли у разработчика соответствующий ключ;
- используется ли Google Play App Signing;
- можно ли выпустить RuStore-сборку с совместимой подписью.

Желательно использовать одинаковую подпись во всех магазинах. Тогда Android сможет обновлять приложение независимо от магазина, из которого установлена предыдущая версия. Если подписи различаются, установка обновления поверх существующего приложения может быть невозможна.

### Безопасность ключа

- Не добавлять keystore, пароли, PEM-сертификаты и другие секреты в Git.
- Хранить резервную копию ключа и паролей в защищённом хранилище.
- Ограничить доступ к EAS credentials и аккаунту владельца.
- Не создавать новый ключ для каждого релиза.

Проверить credentials EAS можно командой:

```powershell
npx eas-cli@latest credentials -p android
```

Не удаляйте и не заменяйте ключ в интерактивном меню без отдельной необходимости.

## 4. Подготовить приложение к релизу

### 4.1. Проверить конфигурацию

В `app.json` должны оставаться корректными как минимум следующие значения:

```json
{
  "expo": {
    "name": "FitnessMate",
    "version": "1.1.0",
    "android": {
      "package": "ru.fitnessmate.mobile"
    }
  }
}
```

Перед каждым новым публичным релизом:

1. обновить `expo.version`, если меняется пользовательская версия;
2. убедиться, что EAS увеличит Android `versionCode`;
3. подготовить текст изменений для раздела «Что нового?».

`version` — версия, которую видит пользователь, например `1.1.0`. `versionCode` — целое внутреннее число Android, которое у каждой следующей загружаемой сборки должно быть больше предыдущего.

### 4.2. Проверить качество проекта

Из корня проекта выполнить:

```powershell
npm run check
```

Команда запускает проверку форматирования, TypeScript, ESLint и тесты. Все проверки должны завершиться успешно.

Дополнительно рекомендуется выполнить:

```powershell
npx expo-doctor
```

Нужно устранить ошибки совместимости Expo до создания production-сборки.

### 4.3. Проверить пользовательские сценарии

На реальном Android-устройстве проверить:

- первый запуск;
- переходы между всеми основными экранами;
- создание, изменение и удаление пользовательских данных;
- хранение данных после перезапуска;
- работу без сети, если она предусмотрена;
- выбор файлов и системные разрешения;
- локализацию и отсутствие необработанных технических текстов;
- светлую и тёмную темы;
- системную кнопку «Назад»;
- отсутствие зависаний и аварийных завершений;
- корректность иконки, splash screen и названия приложения;
- обновление поверх предыдущей подписанной версии.

Если для использования приложения нужна авторизация, подготовить отдельный тестовый аккаунт для модераторов. Он должен открывать все функции, которые необходимо проверить.

### 4.4. Проверить разрешения и данные

RuStore попросит задекларировать:

- какие категории пользовательских данных приложение собирает или обрабатывает;
- для каких целей используются данные;
- передаются ли данные третьим лицам;
- какие чувствительные Android-разрешения используются и зачем.

Приложение должно запрашивать только разрешения, необходимые для его функций. Запрещённые или необоснованные разрешения могут привести к отклонению версии.

Если приложение работает с персональными или конфиденциальными данными, необходимо:

1. подготовить политику конфиденциальности;
2. разместить её по публичному HTTPS-адресу;
3. добавить ссылку в приложение и/или карточку магазина, где это требуется;
4. убедиться, что фактическая обработка данных соответствует тексту политики.

## 5. Собрать релиз

### 5.1. Авторизоваться в EAS

```powershell
npx eas-cli@latest whoami
```

Если авторизация отсутствует:

```powershell
npx eas-cli@latest login
```

### 5.2. Сборка AAB текущим production-профилем

```powershell
npx eas-cli@latest build -p android --profile production
```

После завершения скачать `.aab` по ссылке EAS.

Для публикации AAB затем потребуется подготовить сертификат ключа загрузки и подпись приложения по официальной инструкции RuStore. Для этого может понадобиться Java 11 или новее и доступ к Android keystore.

### 5.3. Рекомендуемый отдельный APK-профиль RuStore

Чтобы EAS создавал APK специально для RuStore, можно добавить в `eas.json` профиль:

```json
{
  "build": {
    "rustore": {
      "autoIncrement": true,
      "android": {
        "buildType": "apk"
      }
    }
  }
}
```

Добавлять его нужно рядом с существующими профилями `preview` и `production`, не удаляя их. После этого команда сборки будет такой:

```powershell
npx eas-cli@latest build -p android --profile rustore
```

После завершения скачать `.apk` по ссылке EAS.

> Не использовать preview-сборку как публичный релиз только потому, что она уже создаёт APK. Отдельный профиль `rustore` делает назначение сборки явным и позволяет независимо менять release-настройки.

### 5.4. Зафиксировать информацию о сборке

Для каждого релиза сохранить:

- версию приложения;
- Android `versionCode`;
- EAS Build ID и ссылку на сборку;
- SHA-256 отпечаток сертификата подписи;
- дату отправки в RuStore;
- текст «Что нового?»;
- результат тестирования;
- статус модерации.

## 6. Проверить готовый APK перед публикацией

Если выбран APK:

1. скачать файл на компьютер;
2. установить его на физическое Android-устройство;
3. повторить критические сценарии из раздела 4.3;
4. проверить обновление поверх предыдущей версии, если она существует;
5. убедиться, что установлено именно приложение `ru.fitnessmate.mobile`;
6. убедиться, что сборка не содержит development menu и не требует Metro-сервер.

Установка через ADB при подключённом устройстве:

```powershell
adb install path\to\fitnessmate.apk
```

Для проверки обновления без удаления данных:

```powershell
adb install -r path\to\fitnessmate.apk
```

## 7. Подготовить карточку приложения

До начала заполнения консоли удобно собрать материалы в отдельной папке вне репозитория или в специально созданной папке без секретов.

### 7.1. Текстовая информация

Подготовить:

- название — не более 30 символов;
- краткое описание — не более 80 символов;
- подробное описание — не более 4000 символов;
- категорию;
- возрастное ограничение;
- до пяти поисковых тегов — необязательно;
- текст «Что нового?»;
- контакт разработчика: как минимум email, сайт, группа VK или MAX;
- ссылку на политику конфиденциальности, если она требуется для функций приложения;
- инструкции и тестовые данные для модератора, если без них нельзя проверить приложение.

Тексты должны точно описывать имеющиеся функции. Не следует обещать возможности, которых нет в загружаемой версии.

### 7.2. Иконка

Требования RuStore:

- размер `512 × 512 px`;
- PNG или JPG;
- не более 3 МБ;
- фон должен заполнять всю площадь изображения;
- по внешнему контуру не должно быть прозрачных или незаполненных участков.

Иконку из `assets/images/icon.png` нужно отдельно проверить на соответствие этим требованиям. Не следует считать, что Expo-иконка автоматически готова для карточки магазина.

### 7.3. Скриншоты

Для мобильной версии скриншоты обязательны.

Нужно подготовить:

- не менее 3 скриншотов телефона;
- не более 10 скриншотов в одной группе;
- PNG или JPG;
- размер одного телефонного скриншота — не более 3 МБ;
- максимальное разрешение мобильного скриншота — `2160 × 3840 px`.

RuStore рекомендует соотношение сторон 16:9 и может растянуть или обрезать неподходящие изображения. Поэтому финальный вид нужно проверить в предпросмотре карточки.

Рекомендуемый порядок экранов FitnessMate:

1. главный экран или обзор возможностей;
2. тренировки/план занятий;
3. прогресс и статистика;
4. дополнительные полезные функции;
5. настройки или персонализация — при необходимости.

На скриншотах не должно быть тестовых персональных данных, отладочной информации или контента, права на который отсутствуют.

## 8. Создать приложение в RuStore Консоли

1. Открыть [RuStore Консоль](https://console.rustore.ru/).
2. Перейти в раздел «Приложения».
3. Нажать «Добавить приложение».
4. Ввести название `FitnessMate`.
5. Открыть созданное приложение.
6. Нажать «Загрузить версию».
7. Выбрать тип мобильного приложения, соответствующий сборке. Не отмечать поддержку ТВ, если приложение не тестировалось и не адаптировано для Android TV.

## 9. Загрузить сборку

### Если выбран APK

1. Загрузить подписанный `.apk`.
2. Дождаться окончания загрузки.
3. Дождаться серверной обработки и проверки файла.
4. Проверить распознанные package name, версию и `versionCode`.

APK должен:

- быть подписан цифровым сертификатом;
- иметь уникальный package name при первой публикации;
- весить не более 5 ГБ;
- для последующих версий иметь ту же подпись и package name;
- для последующих версий иметь больший `versionCode`.

### Если выбран AAB

1. В блоке подписи нажать «Загрузить».
2. Загрузить ZIP-архив подписи приложения.
3. Загрузить сертификат ключа загрузки в формате PEM.
4. После принятия подписи загрузить `.aab`.
5. Дождаться обработки файла.

Не пытайтесь импровизировать с преобразованием ключей. Используйте конкретный keystore, которым EAS подписал AAB, и актуальную инструкцию RuStore по подготовке подписи.

Обработанный файл хранится в RuStore 14 дней. В течение этого срока версию нужно отправить на модерацию, иначе файл будет удалён.

## 10. Заполнить сведения о версии

1. Заполнить раздел «Что нового?».
2. Заполнить декларацию безопасности пользовательских данных.
3. Обосновать каждое найденное чувствительное разрешение.
4. Выбрать категорию и возрастное ограничение.
5. Добавить краткое и подробное описание.
6. Добавить контакт разработчика.
7. Загрузить иконку.
8. Загрузить не менее трёх скриншотов телефона.
9. Указать страны распространения и параметры публикации, если консоль их запрашивает.
10. В комментарии для модератора указать:
    - как проверить основные функции;
    - тестовый логин и пароль, если требуется вход;
    - особенности разрешений или нестандартного поведения;
    - шаги доступа к функциям, которые трудно найти самостоятельно.

## 11. Отправить на модерацию

Перед отправкой пройти финальный чек-лист:

- [ ] package name — `ru.fitnessmate.mobile`;
- [ ] версия отображается правильно;
- [ ] `versionCode` больше предыдущего;
- [ ] APK/AAB подписан правильным ключом;
- [ ] release-сборка протестирована на реальном устройстве;
- [ ] приложение не требует Metro или development client;
- [ ] нет критических ошибок и неработающих экранов;
- [ ] данные и разрешения задекларированы честно;
- [ ] политика конфиденциальности доступна по HTTPS, если необходима;
- [ ] карточка не содержит неподтверждённых обещаний;
- [ ] иконка и скриншоты соответствуют требованиям;
- [ ] тестовый аккаунт работает;
- [ ] комментарий модератору заполнен;
- [ ] контакт поддержки действителен;
- [ ] текст «Что нового?» соответствует этой версии.

После проверки нажать «Отправить на модерацию».

## 12. После отправки

1. Следить за статусом версии и уведомлениями RuStore Консоли.
2. Если версия отклонена, прочитать точную причину и комментарий модератора.
3. Исправить проблему в приложении или карточке.
4. Если создана новая сборка, увеличить пользовательскую версию при необходимости и обязательно получить новый, больший `versionCode`.
5. Повторно протестировать изменённую release-сборку.
6. Отправить исправленную версию на модерацию.

После одобрения проверить публичную карточку, установить приложение именно из RuStore и повторить основные пользовательские сценарии.

## 13. Выпуск следующих обновлений

Для каждого следующего релиза:

1. внести изменения в приложение;
2. обновить `expo.version`, если нужен новый публичный номер версии;
3. выполнить `npm run check` и `npx expo-doctor`;
4. создать сборку тем же EAS-профилем;
5. использовать тот же ключ подписи и package name;
6. проверить, что `versionCode` увеличился;
7. установить обновление поверх предыдущей версии;
8. подготовить новый текст «Что нового?»;
9. загрузить новую версию в существующую карточку RuStore;
10. отправить её на модерацию.

Нельзя создавать новую карточку приложения для обычного обновления.

## 14. Монетизация

Если приложение остаётся бесплатным и не продаёт цифровые товары через RuStore, этот раздел можно пропустить.

Для продажи приложения, подписок или цифровых товаров через RuStore:

1. использовать аккаунт ИП или юридического лица;
2. подключить монетизацию в RuStore Консоли;
3. подписать необходимые документы;
4. интегрировать RuStore SDK оплаты;
5. создать товары и подписки в консоли;
6. протестировать покупки, подтверждение, восстановление и возвраты;
7. не публиковать Google Play Billing как единственный способ оплаты в RuStore-сборке.

Интеграция монетизации — отдельная техническая задача и должна быть реализована и протестирована до отправки платной версии.

## 15. Краткий план именно для текущего проекта

1. Зарегистрировать аккаунт в RuStore Консоли.
2. Решить, публикуем APK или AAB. Для первого релиза предпочтителен отдельный APK-профиль `rustore`.
3. Добавить профиль `rustore` в `eas.json`, если выбран APK.
4. Выполнить `npm run check` и `npx expo-doctor`.
5. Проверить приложение на физическом Android-устройстве.
6. Выполнить EAS build.
7. Установить и протестировать скачанный APK либо подготовить подпись для AAB.
8. Подготовить описание, иконку 512×512, минимум три скриншота и текст «Что нового?».
9. Подготовить политику конфиденциальности и тестовый аккаунт, если они нужны.
10. Создать карточку FitnessMate в RuStore.
11. Загрузить сборку, заполнить декларацию данных и сведения о версии.
12. Отправить на модерацию.
13. После одобрения установить приложение из RuStore и выполнить smoke-тест.
